# CityWalk — ответы на вопросы преподавателя

## Коротко о проекте (вступление на 30 секунд)

> CityWalk — система с готовыми пешеходными маршрутами по городам для туристов.
> Она состоит из двух частей: **сервера** (REST API, папка `server/`) и **приложения**
> для Android, iOS и браузера (папка `client/`).
> Пользователь выбирает город, смотрит маршруты, фильтрует их по времени, дистанции и категории,
> открывает маршрут с описанием, остановками и картой. Администратор через API управляет
> городами, маршрутами и остановками. Сейчас в базе 4 города и 8 маршрутов, из них 5 по Познани.

---

## 1. Что сделано?

**Приложение (для туриста):**
- главный экран с рекомендуемыми маршрутами;
- список городов → маршруты выбранного города;
- карточка маршрута: описание, категория, дистанция, время прохождения, число остановок;
- список остановок по порядку и стартовая точка;
- интерактивная карта (на телефоне): маркеры остановок, линия маршрута, зум и перемещение;
- поиск по названию без учёта диакритики («krakow» находит «Kraków»);
- фильтры по времени, дистанции, категории и сортировка;
- два языка интерфейса (польский и английский), светлая и тёмная тема;
- может работать как с сервером, так и на встроенных тестовых данных.

**Сервер (API):**
- публичные данные: города, маршруты, поиск с фильтрами, рекомендуемые маршруты;
- регистрация и вход пользователей, избранные маршруты;
- вход администратора с подтверждением кодом по e-mail (двухфакторная аутентификация);
- администрирование: создание, редактирование и удаление городов, маршрутов и остановок,
  смена порядка остановок, публикация и снятие с публикации, управление администраторами;
- автоматический пересчёт дистанции и времени маршрута при изменении остановок.

## 2. На каких языках и технологиях?

| Часть | Технологии |
| --- | --- |
| Язык | **TypeScript** везде: и сервер, и приложение |
| Сервер | Node.js, **Express 5** |
| База данных | **PostgreSQL 16** (запускается в Docker) |
| Работа с БД | **Prisma ORM**: схема, миграции, типизированные запросы |
| Валидация | **Zod**: схемы проверки входных данных |
| Приложение | **React Native** + **Expo** (SDK 57): один код для Android, iOS и веба |
| Навигация | expo-router (маршрутизация по файлам) |
| Загрузка данных | TanStack Query (кэширование, состояния загрузки) |
| Карта | react-native-maps (Google Maps на Android, Apple Maps на iOS) |
| Качество кода | ESLint, Prettier, проверка типов `tsc`, юнит-тесты `node:test` |

**Почему TypeScript?** Один язык на сервере и в клиенте. Типы данных (город, маршрут, остановка)
описаны в общем пакете `server/packages/shared`, поэтому ошибки несовпадения формата данных
находятся при компиляции, а не у пользователя.

**Почему React Native и Expo?** Один код для трёх платформ, приложение можно запустить на телефоне
через Expo Go без сборки.

**Почему PostgreSQL и Prisma?** Реляционные данные (город → маршруты → остановки) хорошо ложатся
на SQL; Prisma даёт миграции и типизированный доступ к базе.

## 3. Как это устроено (архитектура)?

```
client/ (приложение) ──HTTP/JSON──▶ server/apps/api (REST /api/v1) ──Prisma──▶ PostgreSQL
                                          │
                       server/packages/shared: типы, схемы Zod, формулы
```

- **Сервер — монорепозиторий** (npm workspaces): `apps/api` — API, `packages/shared` — общий код.
- В API слои разделены так: **роутеры** (HTTP) → **сервисы** (логика) → **Prisma** (база).
  Ответы формируются через **мапперы** в DTO, поэтому служебные поля из базы
  (например, хеш пароля) никогда не попадают в ответ.
- Ошибки обрабатываются в одном месте и возвращаются в едином формате `{ error: { code, message } }`.
- В приложении экраны не знают, откуда берутся данные: они вызывают хуки
  (`useRoutes`, `useCity`…), а слой `client/src/api/client.ts` решает, читать ли API или тестовые данные.

**Модель данных (основные таблицы):** `User` (роли USER / ADMIN / SUPER_ADMIN), `City`, `Route`
(категория, статус черновик/опубликован), `RouteStop` (упорядоченные остановки с координатами),
`RouteImage`, `Favorite`, а также служебные таблицы для кодов входа, сброса пароля и доверенных устройств.

## 4. Как считается дистанция и время маршрута?

- Расстояние между остановками считается по **формуле гаверсинуса** (расстояние по поверхности
  Земли по координатам), затем отрезки суммируются.
- Время = дистанция / **75 м/мин** (4,5 км/ч, обычный темп прогулки) + **5 минут на каждую остановку**.
- Значения пересчитываются автоматически при каждом изменении остановок и хранятся в таблице маршрута,
  чтобы фильтры по времени и дистанции были одним быстрым запросом с индексом.

## 5. Как сделана безопасность?

- Пароли хранятся только в виде хеша **scrypt** с солью; сравнение идёт за постоянное время.
- Сессия хранится в **JWT** внутри cookie `httpOnly`, поэтому JavaScript на странице не может её прочитать.
- Администраторы входят с **кодом из e-mail** (2FA). Суперадмин вводит код при каждом входе, обычный
  админ только с нового устройства. После 3 неверных попыток код сгорает.
- **Ограничение частоты запросов** (rate limiting) на вход, регистрацию и сброс пароля.
- Все входные данные проверяются схемами Zod; ошибки сервера не раскрывают внутренние детали.
- Роли проверяются на каждом запросе: обычный пользователь получает 403 на админских адресах.
- Секреты (ключ JWT, пароли SMTP) лежат в `.env`, который не попадает в git.

## 6. Как проверялось качество?

- Проверка типов TypeScript (`npm run typecheck`) проходит без ошибок.
- ESLint и Prettier без замечаний.
- 9 юнит-тестов: хеширование паролей и расчёт дистанции и времени маршрута; все проходят.
- Ручная проверка API: публичные эндпоинты, регистрация, вход, избранное, коды ответов 400/401/403/404.

Честно о слабом месте: автоматических тестов пока мало, интеграционных тестов API нет.

## 8. Возможные вопросы с подвохом

**— Почему нет отдельного веб-сайта, если в требованиях «пользователь открывает сайт»?**
Приложение из `client/` открывается и в браузере (Expo Web), это тот же код.
Отдельная веб-админка запланирована следующей.

**— Где хранится карта и откуда координаты?**
Карта — сервис платформы (Google/Apple Maps). Координаты остановок хранятся в базе
(широта/долгота) и задаются администратором.

**— Что будет, если удалить город с маршрутами?**
Не получится: API сначала проверяет, есть ли у города маршруты, и возвращает **409 Conflict**
с пояснением; дополнительно в базе стоит связь `onDelete: Restrict` (требование 4.1.25).
Удаление маршрута удаляет и его остановки (каскад, требование 4.1.28).

**— Почему черновики не видны пользователю?**
Публичное API возвращает только маршруты со статусом `PUBLISHED`; черновики видны только в админском API.

**— Использовались ли инструменты ИИ?**
Отвечайте честно и так, как требуют правила вашего вуза. В проекте есть следы работы
с ИИ-ассистентом (файлы `CLAUDE.md`, папка `claudeworks`), поэтому скрывать это не получится и не нужно.
Лучше заранее разобраться в каждой части кода, чтобы уверенно объяснить её своими словами.
